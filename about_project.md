# UniSphere – About the Project

## 1. Project Identity

- **Project Name**: UniSphere
- **Project Type**: Full-Stack MERN (MongoDB, Express.js, React.js, Node.js) Web Application
- **Architecture**: Decoupled Client-Server SPA Architecture with Containerized Nginx & Express Services
- **Purpose**: A centralized university management and collaboration platform facilitating seamless communication, study material distribution, campus event management, lost item recovery, and peer-to-peer student discussion broadcasting.

---

## 2. What UniSphere Currently Does

UniSphere acts as a unified digital portal for university campus life:

- **Student Journey**:
  - Enters official university email (`@chitkarauniversity.edu.in`) and receives a 6-digit OTP via email.
  - Verifies OTP and completes account registration.
  - Logs into the Student Portal to view personalized dashboard stats, semester progress, and campus updates.
  - Accesses course PDF study notes uploaded by faculty members for their department and semester.
  - Views campus events, inspects event details/posters, and reserves seats (or cancels reservations).
  - Reports lost or found items on campus with photos, contacts owners, claims items, or marks items resolved.
  - Participates in the **Student Broadcast** discussion board: asks academic doubts or campus queries, creates posts with optional attachments, adds top-level comments, and replies in 2-tier threaded discussions.
  - Edits profile details and updates profile picture.

- **Faculty Journey**:
  - Receives account credentials (`Faculty@XXXX`) generated by the Admin via email.
  - Logs in; if `mustChangePassword === true`, is automatically forced to change password before proceeding.
  - Accesses Faculty Portal to view upload statistics and department overview.
  - Uploads PDF study notes with title, subject, department, and semester tags.
  - Manages uploaded notes (views own notes, updates metadata, or deletes notes).
  - Schedules and publishes campus events with poster images and circular PDFs.
  - Reviews student registration rosters for published events.

- **Admin Journey**:
  - Logs into the Admin Console (`admin@chitkarauniversity.edu.in`).
  - Provisions new faculty accounts by specifying Name, Chitkara Email, and Department.
  - Manages registered faculty members and student user rosters.
  - Reviews and moderates published study notes, campus events, and lost & found reports.

## 4. Complete Feature Status Matrix

### Implemented Features ✅
- **University Email OTP Registration**: 6-digit OTP verification for `@chitkarauniversity.edu.in` domain before account completion.
- **Multi-Role JWT Authentication**: JWT stored inside `HttpOnly` cookies, protected routes, role authorization guards (`student`, `faculty`, `admin`).
- **Forced Faculty Password Reset**: Mandatory first-login password change for auto-provisioned faculty credentials.
- **Profile Management**: Profile info updates and avatar photo uploads (`uploads/profiles/`).
- **PDF Notes Module**: Uploading, semester/subject filtering, in-browser preview, and file downloading (`uploads/notes/`).
- **Campus Events Module**: Event scheduling, poster/circular file uploads (`uploads/events/`), registration seat tracking, and student roster inspection.
- **Lost & Found Module**: Reporting items with up to 3 image uploads (`uploads/lost-found/`), category filtering, claiming items, and owner resolution.
- **Student Broadcast Board**: Peer-to-peer discussion board with categories ("Academic Doubt", "Campus Query", etc.), search, sorting ("Latest", "Oldest", "Most Discussed"), image attachments (`uploads/broadcast/`), and 2-tier threaded comments (`Post → Comment → Reply`).
- **Admin Management Console**: Provisioning faculty accounts with automated email credentials dispatch and user roster monitoring.
- **Docker Infrastructure**: Multi-stage Vite React build served via Nginx SPA on port 80, Express backend container on port 5000, and persistent uploads volume mount (`backend-uploads`).

### Partially Implemented Features ⚠️
- **Campus Announcements**: Displayed statically on user dashboards. Dedicated backend CRUD controller and push notifications are planned for future scope.

### Planned / Future Features 🔮
- **Cloudinary CDN Storage**: Migrating local file uploads to Cloudinary cloud CDN.
- **Real-Time WebSockets Chat**: 1-on-1 private messaging between Students and Faculty.
- **Club Management Module**: Club registrations, admin approvals, society events, and member memberships.

## 5. Frontend Architecture

- **Framework**: React.js 19 with Vite 8 bundler.
- **Entry Point**: `frontend/src/main.jsx` rendering `<BrowserRouter>` and `<AuthProvider>`.
- **Routing**: `frontend/src/routes/AppRoutes.jsx` handling route mapping, `<ProtectedRoute>` guards, and `<PageTransition>` animations.
- **Styling**: Tailwind CSS v4 with custom glassmorphism design tokens.
- **State Management**: React `Context API` (`AuthContext.jsx`) managing user session, loading, login, and logout states.
- **API Service**: `frontend/src/api/axios.js` configuring shared Axios client with `baseURL: "http://localhost:5000/api"` and `withCredentials: true`.
- **Key Folders**:
  - `src/api/` — API modules (`authApi`, `noteApi`, `eventApi`, `lostFoundApi`, `broadcastApi`).
  - `src/components/` — Reusable elements (`auth/`, `common/`, `landing/`, `layout/`, `notes/`).
  - `src/layouts/` — Master layout shells (`StudentLayout`, `FacultyLayout`, `AdminLayout`).
  - `src/pages/` — Application view pages (`auth/`, `student/`, `faculty/`, `admin/`, `shared/`, `LostFound/`).

---

## 6. Backend Architecture

- **Runtime & Server Entry**: Node.js v20/22 running `Backend/src/server.js`.
- **Express Application**: `Backend/src/app.js` configuring CORS middleware, `express.json()`, `cookieParser()`, static route handling (`/uploads`), API route handlers, and global error middleware.
- **Database Connection**: `Backend/src/config/db.js` managing Mongoose connection to MongoDB Atlas with diagnostic logging and default Admin account seeding (`admin@chitkarauniversity.edu.in` / `Admin@123`).
- **Controllers**:
  - `authController.js` — Auth, registration, OTP, login, password reset, profile, faculty creation.
  - `noteController.js` — Note upload, fetching, filtering, editing, deletion.
  - `eventController.js` — Event creation, poster uploads, seat registration/cancellation, roster fetching.
  - `lostFoundController.js` — Item reporting, multi-photo uploads, claiming, resolving, deletion.
  - `broadcastController.js` — Broadcast posts creation, fetching, updating, deletion, threaded commenting, and replies.
- **Middlewares**:
  - `authMiddleware.js` (`protect`) — JWT verification from `req.cookies.token`.
  - `roleMiddleware.js` (`authorize`) — Role permission check.
  - `uploadMiddleware.js`, `imageUploadMiddleware.js`, `eventPosterUpload.js`, `lostFoundUpload.js`, `broadcastUpload.js` — Multer file upload instances.
- **Services & Utils**:
  - `emailService.js` — Nodemailer SMTP email dispatch.
  - `generateToken.js` — JWT signing utility.
  - `generateOTP.js` — 6-digit random numeric OTP generator.

## 7. Database Models (Mongoose)

### 1. `User`
- **Purpose**: User account storage across all roles.
- **Fields**: `name`, `email`, `password`, `role` (`student`, `faculty`, `admin`), `department` (`CSE`, `BCA`, `Pharmacy`, `Nursing`), `semester`, `profilePic`, `bio`, `phone`, `isVerified`, `mustChangePassword`, `otpHash`, `otpExpiry`.

### 2. `Note`
- **Purpose**: Study material PDF metadata.
- **Fields**: `title`, `subject`, `department`, `semester`, `description`, `fileUrl`, `uploadedBy` (ref: `User`), `downloads`.

### 3. `Event`
- **Purpose**: Campus events and seat reservations.
- **Fields**: `title`, `description`, `category`, `department`, `venue`, `date`, `time`, `registrationDeadline`, `maxParticipants`, `poster`, `circular`, `createdBy` (ref: `User`), `registeredStudents` (array of `User` references).

### 4. `LostFound`
- **Purpose**: Lost & Found item reports.
- **Fields**: `owner` (ref: `User`), `type` (`lost`/`found`), `itemName`, `category`, `description`, `location`, `date`, `images` (array), `status` (`active`/`resolved`), `phone`, `claimedBy` (ref: `User`).

### 5. `BroadcastPost`
- **Purpose**: Student discussion posts.
- **Fields**: `author` (ref: `User`), `title`, `category`, `description`, `attachment`, `commentCount`.

### 6. `BroadcastComment`
- **Purpose**: Threaded comments and replies.
- **Fields**: `post` (ref: `BroadcastPost`), `author` (ref: `User`), `parentComment` (ref: `BroadcastComment`), `content`.

## 9. File Uploads

File uploads are processed using **Multer** and saved to the local `uploads/` directory on disk:
- **PDF Notes**: Filtered for `application/pdf`, stored in `uploads/notes/`.
- **Profile Avatars**: Filtered for images, stored in `uploads/profiles/`.
- **Event Posters & Circulars**: Stored in `uploads/events/`.
- **Lost & Found Images**: Up to 3 item photos, stored in `uploads/lost-found/`.
- **Broadcast Attachments**: Post images, stored in `uploads/broadcast/`.

Express serves static files via `app.use("/uploads", express.static("uploads"))`.
In Docker environments, a named volume `backend-uploads` is mounted to `/app/uploads` so uploaded files persist across container restarts.

## 10. Docker Architecture

- **Frontend Container**: Nginx Alpine image running static build assets (`dist/`) on port 80 with SPA client routing fallback (`try_files $uri $uri/ /index.html;`).
- **Backend Container**: Node 20 Alpine container running production server (`node src/server.js`) on port 5000.
- **Uploads Volume**: Named Docker volume (`backend-uploads`) mapped to `/app/uploads`.

## 12. Important Project Rules

1. **Email Domain Rule**: Student registration strictly enforces email domain suffix `@chitkarauniversity.edu.in`.
2. **First Login Password Change**: Faculty accounts provisioned by Admin receive temporary credentials (`Faculty@XXXX`) and must change password on first login (`mustChangePassword === true`).
3. **No Frontend Author Impersonation**: Resource authors are always set from `req.user._id` via server-side JWT verification, never trusted from frontend request bodies.
4. **Ownership Verification**: Controllers enforce `resource.author.toString() === req.user._id.toString()` (`403 Forbidden`) before edit/delete operations.
5. **No Full-Page Reloads**: Internal routing strictly uses React Router (`navigate()`, `<Link>`, `<NavLink>`). `window.location.reload()` is never used.

## 14. Known Issues & Fallbacks

- **Campus Network Firewall**: Campus Wi-Fi occasionally blocks MongoDB Atlas SRV DNS lookup or Nodemailer Gmail SMTP ports.
  - *Database Fallback*: `Backend/src/config/db.js` automatically detects Atlas connection failure and falls back to local MongoDB (`mongodb://127.0.0.1:27017/unisphere`).
  - *Email Fallback*: Generated OTPs and faculty temporary passwords are logged to server console if Nodemailer dispatch fails.

## 16. How to Run with Docker

1. Populate `Backend/.env` with your real secrets using `.env.example` as a reference.
2. Build and start services:
   ```bash
   docker compose build
   docker compose up -d
   ```
3. Access application at `http://localhost:80` (or `http://localhost`).
4. Stop services:
   ```bash
   docker compose down
   ```
5. View container logs:
   ```bash
   docker compose logs -f
   ```
